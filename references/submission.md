# Submission protocol

Scheduled runs may discover, rank, research, and draft, but stop at ready_for_review. They must not submit, consent, sign, or answer sensitive questions.

Before an interactive submission, show company, exact role, canonical URL, deadline, files, answers, unresolved facts, consent/privacy/demographic/work-authorization/compensation questions, and CAPTCHA or login requirements. Obtain explicit approval for that exact package.

Then use the signed-in browser, fill only verified data, pause on mismatches or sensitive fields, upload only reviewed files, re-read the form, and honor the browser's final confirmation. Hand control to the user for CAPTCHA or blocked automation. Record confirmation text or application ID in ledger.csv; never claim submission without observing confirmation.
