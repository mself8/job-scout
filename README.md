# job-scout

채용 공고를 매일 훑어, **지원자가 실제로 만든 산출물에만 근거해서** 적합도를 채점하고, 거짓 없는 지원 서류를 준비하는 에이전트 스킬.

지원 건수를 늘리는 도구가 아니다. **쓰면 안 되는 말을 쓰지 않게 만드는 도구**다.

## 왜 만들었나

LLM에게 "내 이력서 좀 써줘"라고 하면 대개 두 가지가 일어난다.

1. **없는 경험을 만들어낸다.** "대규모 트래픽 서비스 운영", "팀을 리드하여" 같은 문장이 근거 없이 붙는다. 면접에서 바로 무너진다.
2. **아무 공고나 다 맞다고 한다.** 학력 요건에 걸려 서류에서 자동 탈락하는 공고를 상위에 올린다.

이 스킬은 둘 다를 구조적으로 막는 걸 목표로 한다.

## 설계

### 1. 근거 원장 (evidence profile)

지원자의 작업 디렉터리를 훑어 **로컬 산출물에서 확인되는 주장만** 프로필에 기록한다. 각 항목은 출처 파일 경로를 갖는다.

세 계층을 절대 섞지 않는다.

| 계층 | 예 | 서류에 쓸 수 있나 |
|---|---|---|
| 검증됨 | "환각 139건 주입, 검출률 90.6%" — README에 수치 존재 | 그대로 사용 |
| 추론 | "그 정도면 SQL도 하겠지" | 사용 금지 |
| 미확인 | "영어 실력", "실무 SQL 깊이" | 갭으로 명시 |

추론을 검증으로 승격하는 것을 금지하는 규칙이 스킬에 명시돼 있다. 이게 이 도구의 핵심이다.

### 2. 하드 게이트 상한

100점 루브릭(핵심요건 25 / 근거 25 / 자격 15 / 도메인 10 / 포트폴리오 10 / 로지스틱스 10 / 문화 5)으로 채점하되:

- **훈련 불가능한 필수 요건이 없으면 49점으로 상한을 씌운다.** 석사 재학 요구, 졸업예정자 한정 같은 것들이다. 아무리 기술 적합도가 높아도 서류에서 떨어지므로 상위에 올리지 않는다.
- **훈련 가능한 핵심 스택이 없으면 59점 상한.** 단, 그 갭을 메우는 작동하는 산출물이 있으면 해제한다.

첫 2일 운영에서 수집한 17건 중 **4건이 이 상한에 걸렸다.** 전부 "졸업자 또는 졸업예정자" 요건이었다. 상한이 없었으면 기술 적합도만 보고 상위에 올렸을 공고들이다.

### 3. 소스 신뢰도

운영해보니 **웹 검색 인덱스가 한국 채용 사이트에 대해 낡았다.** 1년 전 마감된 공고를 "현재 접수 중"으로 반환하고, 7년 전 공고를 최상단에 올린다. 검색 결과만 믿으면 리포트가 죽은 공고로 채워진다.

그래서 소스를 등급으로 나눴다. 자세한 건 [docs/source-reliability.md](docs/source-reliability.md).

- 검색 결과는 **단서**로만 쓴다. 점수를 매기지 않는다.
- 마감일과 모집 상태는 **반드시 공고 원문 페이지에서** 재확인한다.
- 실제로 렌더링되는 소스와 안 되는 소스를 문서에 기록해 다음 실행이 시간을 낭비하지 않게 한다.

실제로 첫 실행에서 93점으로 1순위였던 공고가 다음 날 내려갔다. 재확인 단계가 없었으면 이미 사라진 공고용 지원서를 준비하고 있었을 것이다.

### 4. 중복 제거 대장

`scripts/job_ledger.py` — URL 정규화(추적 파라미터 제거) 후 SHA-256 기반 키로 중복을 제거하는 CSV 원장.

`first_seen`, `status`, `package_path`, `user_decision`, `submitted_at`은 **보호 필드**다. 재실행이 사용자의 결정을 덮어쓰지 못한다. 자동화가 사람의 판단을 지우는 건 최악의 실패 모드라서 스키마 수준에서 막았다.

```bash
python3 scripts/job_ledger.py merge ledger.csv --input new.jsonl --date 2026-08-31
python3 scripts/job_ledger.py check ledger.csv   # 중복 job_id / 중복 공고 검사
```

### 5. 제출 프로토콜

가장 조심한 부분이다. [references/submission.md](references/submission.md)

- **예약 실행은 절대 제출하지 않는다.** `ready_for_review`에서 멈춘다.
- 대화 중 제출도 **해당 회사·직무·답변·첨부에 대한 명시적 승인**이 있어야 한다. 한 건의 승인이 다음 건으로 이어지지 않는다.
- 법적 성명, 연락처, 병역, 장애 여부, 희망 급여, 동의 항목은 **추론해서 채우지 않는다.** 폼에 나오면 멈춘다.
- 확인 문구나 접수번호를 실제로 관측하기 전에는 제출됐다고 기록하지 않는다.

## 구성

```
SKILL.md                        스킬 정의 (상태 갱신 / 일일 스카우트 / 패키지 작성 / 제출 / 학습 루프)
references/scoring.md           채점 루브릭과 하드 게이트 상한
references/reference-research.md 합격 자소서·포트폴리오에서 평가 패턴만 추출하는 절차 (문구 복제 금지)
references/submission.md        제출 프로토콜
scripts/job_ledger.py           정규화·중복제거 CSV 원장
docs/source-reliability.md      채용 소스별 신뢰도와 렌더링 여부
agents/openai.yaml              에이전트 인터페이스 정의
```

상태(프로필·선호도·대장·일일 리포트·지원 패키지)는 **이 레포에 없다.** 별도 비공개 디렉터리에 둔다.

## 한계

- 한국 채용 시장 기준으로 설계했다. 소스 목록과 학력 게이트 규칙이 그렇다.
- 링커리어 외 대부분의 채용 사이트는 클라이언트 렌더링이라 자동으로 못 읽는다. 커버리지가 소스에 종속된다.
- 채점 루브릭의 가중치는 경험적으로 정한 값이고 검증되지 않았다. 밴드 경계(80/70/60)도 마찬가지다.
